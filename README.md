# QuizAI - Student / Teacher AI Quiz Platform

Teachers create batches and quizzes (manually or **generated by AI from a PDF**).
Students join batches, take timed quizzes, see their results and ask an **AI tutor**.

**Live app:** https://student-teacher-ai-quiz-management.vercel.app
**API docs:** https://student-teacher-ai-quiz-management.onrender.com/api-docs

**Tech:** React + Vite + Tailwind (frontend) · Node.js + Express + MongoDB (backend) · Redis (optional cache) · Groq AI

---

## 1. Run it locally

You need **Node.js 18+**. MongoDB and Redis can run in Docker (easiest) or be installed/hosted.

### Step 1 - Start MongoDB (and optionally Redis)

```bash
docker run -d --name quiz-mongo -p 27017:27017 mongo:7
docker run -d --name quiz-redis -p 6379:6379 redis:7-alpine   # optional
```

(Already created them before? Use `docker start quiz-mongo quiz-redis`.)

### Step 2 - Backend

```bash
cd backend
cp .env.example .env      # then open .env and fill in the values
npm install
npm run dev               # -> http://localhost:5001   (API docs: http://localhost:5001/api-docs)
```

### Step 3 - Frontend (in a second terminal)

```bash
cd frontend
npm install
npm run dev               # -> http://localhost:5173
```

### Or: everything with Docker Compose (one command)

```bash
cp backend/.env.example backend/.env    # fill in JWT_SECRET and GROQ_API_KEY
docker compose up --build
```
Open http://localhost:3001

## 2. Settings (`backend/.env`)

| Name | Required? | What it is |
|------|-----------|------------|
| `MONGO_URI` | yes | MongoDB address, e.g. `mongodb://127.0.0.1:27017/quizapp` |
| `JWT_SECRET` | yes | Any long random text (signs the login cookie) |
| `PORT` | no | Backend port. Default **5001** (5000 is used by AirPlay on macOS) |
| `GROQ_API_KEY` | for AI features | Free key from https://console.groq.com/keys |
| `GROQ_MODEL` | no | AI model to try first. Default `openai/gpt-oss-20b`; if a model is retired by Groq the app automatically tries the next one |
| `REDIS_URL` | no | e.g. `redis://127.0.0.1:6379`. **Leave empty to run without cache** |
| `FRONTEND_URL` | no | An extra frontend URL allowed to call the API (the deployed one is already allowed) |

Frontend: `VITE_API_URL` = backend address + `/api`. If not set, `npm run dev` uses `http://localhost:5001/api`
and production builds use the deployed backend.

### Free accounts you may want
- **Groq** (AI): https://console.groq.com -> sign in -> *API Keys* -> *Create API Key*. Free, no card.
- **MongoDB Atlas** (hosted DB, optional): https://www.mongodb.com/cloud/atlas -> free M0 cluster ->
  *Database Access*: add a user -> *Network Access*: allow your IP (or `0.0.0.0/0`) -> *Connect* -> copy the `mongodb+srv://...` string.
- **Upstash** (hosted Redis, optional): https://upstash.com -> create Redis database -> copy the `rediss://...` URL.

## 3. Deploying (free): backend on Render, frontend on Vercel

Both parts deploy automatically when you push to the `main` branch on GitHub.

**Backend - Render "Web Service"** (`student-teacher-ai-quiz-management.onrender.com`)

| Setting | Value |
|---------|-------|
| Root Directory | `backend` |
| Build Command | `npm install` |
| Start Command | `npm start` |
| Environment | `MONGO_URI`, `JWT_SECRET`, `GROQ_API_KEY`, and optionally `REDIS_URL` (Upstash `rediss://...`) |

Check it: open `https://student-teacher-ai-quiz-management.onrender.com/api/health` ->
`{"status":"ok","database":"connected"}`. If it says `not connected`, see the logs on Render (MongoDB Atlas paused or IP not allowed).

**Frontend - Vercel project** `student-teacher-ai-quiz-management` (`student-teacher-ai-quiz-management.vercel.app`)

| Setting | Value |
|---------|-------|
| Root Directory | `frontend` |
| Framework Preset | Vite (build `npm run build`, output `dist`) |
| Environment | `VITE_API_URL=https://student-teacher-ai-quiz-management.onrender.com/api` |
| Rewrites | `frontend/vercel.json` sends every path to `/index.html` (so page refresh works) |

If the frontend URL changes, add it to the `cors` list in `backend/index.js` (or set `FRONTEND_URL` on Render).

**MongoDB Atlas:** *Network Access* must allow `0.0.0.0/0` (Render has no fixed IP).

**Redis (Upstash):** database `student-teacher-ai-quiz-cache` (Singapore). Its `rediss://...` URL is the `REDIS_URL` on Render.

**Keep-alive (Upstash QStash):** free services delete or pause themselves when unused
(Upstash Redis after 14 days, MongoDB Atlas after ~60 days). A QStash schedule named
`quiz-app-keepalive` calls `/api/health` every 3 days, which wakes Render and sends a real
command to Redis and MongoDB. See/edit it at https://console.upstash.com -> QStash -> Schedules.

## 4. How the app works

```
backend/
  index.js                 starts Express, connects MongoDB, registers routes
  config/db.js             MongoDB connection
  config/cache.js          Redis cache (optional - app works without it)
  config/ai.js             Groq AI helper
  middleware/auth.js       verifyToken (logged in?) + requireRole('teacher' | 'student')
  models/                  User, Batch, Quiz, Result (Mongoose schemas)
  controllers/             the logic for each feature
  routes/                  URL -> controller (+ Swagger docs comments)

frontend/src/
  App.jsx                  all pages/URLs + login/role protection (RequireRole)
  api/axios.js             one axios instance + getErrorMessage()
  context/AuthContext.jsx  who is logged in (user.name, user.role)
  components/              layout (sidebar), small UI pieces, quiz card
  pages/teacher/           teacher pages
  pages/student/           student pages
  index.css                shared styles: .btn-primary, .card, .input, ...
```

**Login:** the backend puts a JWT in an http-only cookie. The browser sends it automatically
(`withCredentials: true`). `GET /api/auth/check` tells the frontend who is logged in.

**Cache:** Redis stores some lists for a few minutes to make them faster. When data changes
(new quiz, submission, join batch...) the related cache keys are deleted. If Redis is down,
the app simply reads from MongoDB.

## 5. Troubleshooting

| Problem | Fix |
|---------|-----|
| `Port 5001 is already in use` | Another backend is still running. Close it, or change `PORT`. |
| `Could not connect to MongoDB` (retries every 15s) | Is MongoDB running (`docker start quiz-mongo`)? On Atlas: cluster not paused, IP allowed? |
| "The database is not connected yet" in the app | Same as above - the backend is running but cannot reach MongoDB. |
| "Cannot reach the server" in the app | The backend is not running, or `VITE_API_URL` points to the wrong place. |
| "AI is not configured" | Add `GROQ_API_KEY` to `backend/.env` and restart the backend. |
| "Redis problem ..." warning | Harmless - the app keeps working without cache and reconnects by itself. `ENOTFOUND` = the Upstash database no longer exists (check the Upstash console), `WRONGPASS` = the password in `REDIS_URL` changed, `Connection timeout` = wrong address or `redis://` vs `rediss://` mix-up (Upstash needs `rediss://`). |
| First load is very slow on the deployed site | Render's free plan sleeps after ~15 min idle; the first request wakes it (can take ~1 min). Open the backend URL a minute before a demo. |
| Database not connected after a long break | MongoDB Atlas pauses free clusters that are unused for a long time. Open Atlas and click *Resume* - the backend reconnects by itself. |
